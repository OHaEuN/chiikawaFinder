# 4. 서비스 정책서

> **원칙:** 공식 데이터를 그대로 보여 주되 우리가 본 시각과 한계를 같이 적는다. 틀리면 사용자가 돈을 잃는 판정(가품, 공구 주최자 검증)은 하지 않는다. 결제·배송에 관여하지 않는다. 비용은 0이고 수익은 제휴 링크만이다.

기준일 2026-11-11. 정책 ID는 P-영역-번호. 코드에서 상수로 고정된 값은 괄호에 적었다.

---

## 1. 수집

| ID | 정책 |
|---|---|
| P-DATA-01 | 공식몰(chiikawamarket.jp)의 공개 `products.json`만 읽는다. 로그인 뒤 페이지, 이용약관이 수집을 금지한 서비스(윗치폼 등)는 읽지 않는다. |
| P-DATA-02 | 하루 한 번, 06:00 KST에 전량을 읽는다. 더 자주 읽지 않는다. 그사이의 변화는 기록에 없다고 화면에 적는다. |
| P-DATA-03 | 통화는 엔으로 고정해 요청하고(`currency=JPY`), 받은 뒤 전량을 다시 검사한다. 하나라도 엔이 아니면 그날 수집을 버린다. |
| P-DATA-04 | 발매일은 상품 태그의 8자리 날짜로만 정한다. `published_at`은 재공개 때 바뀌어 믿지 않는다. 예약 태그(PRE)는 발매 태그가 없을 때만 쓴다. |
| P-DATA-05 | 목록 창은 최근 6개월(`WINDOW_MONTHS`)이다. 발매일 또는 마지막 재입고일이 그 안이면 남긴다. 수동으로 넣은 상품(대원미디어 등)은 창과 무관하게 유지한다. |
| P-DATA-06 | 테스트가 하나라도 실패하면 수집하지 않는다. 수집이 실패하면 커밋하지 않고 전날 데이터로 서비스는 계속 선다. |
| P-DATA-07 | 변화가 있을 때만 커밋한다. 커밋 메시지는 `chore : 굿즈·환율 데이터 자동 갱신 YYYY-MM-DD`. |
| P-DATA-08 | 수동 데이터(인물, 온라인, 장소, 한국 상품, 공구 채널)는 항목마다 출처 URL을 적는다. 출처가 없는 항목은 넣지 않는다. |

## 2. 변화 판정

| ID | 정책 |
|---|---|
| P-CHANGE-01 | 품절은 "어제는 살 수 있었는데 오늘은 없다"다. 처음부터 없던 상품은 품절로 세지 않는다. |
| P-CHANGE-02 | 재입고는 "어제는 없었는데 오늘은 있다"다. 이와 별도로 공식 태그의 RE+날짜를 재입고 이력으로 모은다. 두 출처를 섞지 않고 상세 화면에서 구분해 적는다. |
| P-CHANGE-03 | 신상은 "처음 보는 id이고 발매일이 60일(`NEW_ARRIVAL_MAX_AGE_DAYS`) 이내"다. 오래된 상품이 재입고로 창에 다시 들어온 경우를 신상으로 세지 않기 위해서다. |
| P-CHANGE-04 | 첫 실행(이전 목록 없음)은 변화 0건이다. 첫날 전량이 신상으로 기록되는 것을 막는다. |
| P-CHANGE-05 | 기록에는 바뀐 상품의 id만 적는다. 상품 내용은 goods.json 한 곳에만 있다. 180일(`HISTORY_WINDOW_DAYS`)보다 오래된 날은 버린다. |
| P-CHANGE-06 | 환율을 못 받은 날은 0으로 적고 그래프에서 뺀다. 변화가 없는 날도 환율은 적어 그래프가 끊기지 않게 한다. |

## 3. 상품명 번역

| ID | 정책 |
|---|---|
| P-NAME-01 | 번역 API를 쓰지 않는다. 빌드 타임 사전 치환이며 같은 입력에 같은 결과가 나온다. |
| P-NAME-02 | 사전에는 낱말 단위로만 넣고 한 글자 키는 넣지 않는다(「水」를 넣으면 「水色」이 깨진다). 긴 키부터 치환한다. |
| P-NAME-03 | 괄호 안 대사·의성어(「わーいわい」 등)는 일부러 옮기지 않는다. 분위기이기 때문이다. |
| P-NAME-04 | 상세 화면에서 한국어 이름과 공식몰 원문을 함께 보여 준다. 소개문이 일본어면 "공식몰 소개문 (일본어 원문)"이라고 밝힌다. |
| P-NAME-05 | 무엇을 먼저 채울지는 검색어 데이터(서치콘솔, `goods_search`)로 정한다. 짐작으로 채우지 않는다. |

## 4. 재고와 재입고 표현

| ID | 정책 |
|---|---|
| P-STOCK-01 | 발매일이 오늘보다 뒤면 "발매 예정"이다. 살 수 없어도 품절이라고 쓰지 않는다. |
| P-STOCK-02 | 재고를 모르는 상품(수동 데이터)은 아무 표시도 하지 않는다. "확인되지 않았습니다"로 적는다. |
| P-STOCK-03 | 재입고 안내는 세 단계다. 한 번도 안 들어왔으면 "지켜봐야 합니다", 1~2회면 "다시 들어올 수 있습니다", 3회(`REPEAT_THRESHOLD`) 이상이면 "정기적으로 다시 들어오는 편이라 기다려 볼 만합니다". 확률이나 예정일을 말하지 않는다. |
| P-STOCK-04 | 평균 간격은 날짜가 두 개 이상일 때만 계산한다. 마지막 재입고가 며칠 전인지 같이 적는다. |
| P-STOCK-05 | 품절까지 걸린 날은 기록 시작일(2026-09-18) 이후만 센다. 그 앞은 우리가 못 봤다고 화면에 밝힌다. |
| P-STOCK-06 | 계산기 후보는 지금 살 수 있는 일본 상품만이다. 품절 상품을 담아 봐야 살 수 없다. |

## 5. 환율

| ID | 정책 |
|---|---|
| P-FX-01 | 상품값은 엔화로 고정이고 원화는 날짜별 환율 하나로 전부 환산한다. 상품마다 원화를 따로 저장하지 않는다. |
| P-FX-02 | "살 만한 때" 판정은 기록 안에서 오늘보다 쌌던 날의 비율로 한다. 1/3(`GOOD_PERCENTILE`) 이하면 좋음, 2/3 이상이면 나쁨, 사이는 중간. 예측하지 않는다. |
| P-FX-03 | 화면의 환율은 소수 둘째 자리까지 보여 주고 계산도 같은 값으로 한다. 8.445558처럼 긴 값은 고쳐 쓰기 어렵다. |
| P-FX-04 | 체감 예시는 1만 엔(`SAMPLE_YEN`)으로 든다. 공구 무배컷과 비슷해 감이 온다. |

## 6. 직구 계산기

| ID | 정책 |
|---|---|
| P-COST-01 | 공구 환율은 수수료가 섞인 적용 환율로 본다. 실환율과의 차액을 원과 %로 보여 주되, "수수료"라고 단정하지 않는다. 프리셋은 9.5와 10(`GROUPBUY_RATE_PRESETS`). |
| P-COST-02 | 무배컷은 공식 안내대로 1회 주문 11,000엔(`FREE_DOMESTIC_SHIPPING_YEN`). 못 미치면 일본 내 배송료 990엔(`DOMESTIC_JP_SHIPPING_YEN`, 관동·중부 요금)을 더한다. 지역마다 다르다고 적는다. |
| P-COST-03 | 면세 한도는 일본발 150달러(`DUTY_FREE_LIMIT_USD`). 판정용 물품가격에는 국제운임을 빼고, 넘기면 전체 금액에 과세하며 과세가격에는 국제운임을 넣는다. 일본 내 운임은 물품가격에 들어간다. 근거는 [docs/import-cost.md](../import-cost.md). |
| P-COST-04 | 관세는 인형·문구·잡화 8%, 의류 13%. 부가세 10%는 관세를 더한 금액에 붙는다. 품목은 사용자가 고른다. |
| P-COST-05 | 해외배송비만 인원으로 나눈다. 상품값과 세금은 내 몫 전액이다. 인원이 0이나 음수면 1로 본다. |
| P-COST-06 | 세금은 예상치다. 같은 날 들어온 다른 주문과 합산될 수 있고 품목 분류에 따라 달라진다고 결과 아래에 적는다. |
| P-COST-07 | 장바구니와 조건은 그 브라우저(localStorage)에만 남는다. 서버로 보내지 않는다. |

## 7. 공구

| P-GB-03 | 채널마다 "무엇을 확인하라"는 한 문장을 둔다. "참여하라"고 권하지 않는다. |
| P-GB-04 | 결제·배송에 관여하지 않는다고 계산기 아래에 적는다. |

## 9. 오프라인 장소

| ID | 정책 |
|---|---|

| P-PLACE-04 | 1.8km(`WALK_LIMIT_KM`) 이하는 시속 4.2km(`WALK_KMH`)로 걷는 시간을 적고, 넘으면 전철이라고만 한다. 노선을 모르니 시간을 지어내지 않는다. |
| P-PLACE-05 | 현장 대기·재고는 싣지 않는다. 확인할 수단이 없다. |

## 14. 예외와 오류

| 상황 | 서비스의 판단 |
|---|---|
| 수집 실패(공식몰 응답 오류, 통화 불일치, 테스트 실패) | 커밋하지 않는다. 전날 데이터로 서비스 유지. Actions 실패 알림은 GitHub 기본 메일 |
| 환율 수집 실패 | 그날 환율 0으로 기록, 그래프·판정에서 제외 |
| 기록이 하루뿐 | 오늘 페이지에 "기록을 모으는 중입니다". 환율 판정은 2일부터 |
| 앞으로 나올 굿즈 없음 | 캘린더에 "다음 발매를 기다리는 중입니다" |
| 이미지 로드 실패 | 상품은 🎁, 장소는 유형 이모지, 인물은 그룹 이모지로 대체 |
| 가격이 "가격 미정" 등 숫자가 아님 | 원화 추이·구조화 데이터 생략, 계산기 후보에서 제외 |
| 계산기에 품절 상품을 `?add=`로 넘김 | 후보에 없으므로 담기지 않음 |
| 인원 0명 | 1명으로 계산 |
| 코스 경유지 10곳 초과 | 앞 10곳만 구글 지도로, 넘쳤다고 표시 |
| 없는 주소 | 404 페이지, 홈으로 |
| `prefers-reduced-motion` | 3D 캐릭터 정지 |
| 터치 화면 | 커서 그림과 선택기 끔 |

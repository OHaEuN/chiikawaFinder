# 구현 메모

## 매일 도는 파이프라인

```
매일 06:00 KST ─ GitHub Actions (scrape.yml)
   ├ pnpm check     테스트 104개. 로직이 깨지면 여기서 멈춤
   ├ pnpm fx        엔/원 환율 → fx.json
   ├ pnpm scrape    공식몰 전량 수집 → goods.json
   └ diffDay        어제 파일과 비교해 바뀐 상품의 id 만 history.json 에
            │
            └ 변화가 있을 때만 커밋  →  Vercel 이 보고 배포
                                        │
                        빌드 타임에 일본어 이름 → 한국어 변환
                        굿즈 2,289 · 인물 45 · 장소 81 = 정적 페이지 2,427장
```

설계에서 중요한 결정 셋이다.

**테스트를 배포가 아니라 수집 워크플로에 둔다.**
깨진 데이터가 커밋되는 것을 막는 자리가 거기다. 배포에서 막으면 이미 커밋된 뒤다.

**변화 기록에는 상품 전체가 아니라 id 만 적는다.**
상품은 `goods.json` 한 곳에만 저장되고, 기록 파일은 날이 쌓여도 커지지 않는다.

**Shopify 응답의 통화를 믿을 수 없다.**
`currency` 파라미터를 안 붙이면 요청 지역 기준 환산가가 통화 표시 없이 온다.
첫 수집본은 가격이 전부 원화였는데 사이트는 엔화로 읽었다.
지금은 파라미터를 고정하고 수집 직후 전량을 다시 검사하며, 그 검사를 테스트로 묶었다.

## 변화를 뽑는 방법

공식몰은 어제와 뭐가 달라졌는지 알려 주지 않는다. 품절은 조용히 일어나고
재입고 목록은 재입고 전날 사라진다. 그래서 덮어쓰기 **전**의 목록과 비교한다.

- `diffDay` 본체는 20줄 정도. 이전 목록을 `Map` 으로 만들고 `available` 의 `true→false` 를 품절로 본다
- 목록이 최근 6개월 창이라, 오래된 상품이 재입고로 들어오면 처음 보는 id 처럼 보여 신상으로 잡혔다.
  발매일 60일 이내만 신상으로 세게 해서 막았다
- 첫 실행이면 비교 대상이 없으므로 신상도 품절도 없다고 처리한다. 첫날 전량이 신상으로 기록되는 것을 막는다

## 상품명 한국어 변환

번역 API 를 붙이기 전에 상품명을 토큰으로 쪼개 세었다.
서로 다른 토큰 1,568개 중 **상위 300개가 전체 출현의 71%** 였다. 상품명은 자유 문장이 아니라 템플릿이다.

사전을 고른 이유는 셋이다. 빌드 타임 순수 함수라 런타임 비용·API 키가 없고,
같은 입력에 같은 결과가 나와서 테스트가 되고, 캐릭터 이름을 매번 다르게 옮기는 문제가 없다.

처리 순서는 패턴 → 사전 치환 → 조사 보정 → 공백·괄호 정리다.
긴 키부터 정렬해 하나의 정규식으로 합쳐 한 번에 치환한다 (`ちいかわパーク` 가 `ちいかわ` 보다 먼저 잡히게).

> **짧은 키는 쓰지 않는다.** 「水」 한 글자를 넣었더니 `水色` 이 "물 色", `撥水` 가 "撥 물" 이 됐다.
> "긴 것부터 치환"은 긴 형태도 사전에 있을 때만 지켜진다. 낱말 단위로만 넣는다.
> 출력에서 한국어 옆에 붙은 1~2글자 카나 조각을 찾는 검사로 같은 종류의 사고를 한 번에 찾았다.

현재 완전 한국어 69.2%(1,585/2,289), 사전 795항목.

## 이미지

애니 공식 사이트의 캐릭터 이미지는 90x145 썸네일뿐이라 확대하면 흐리다.
극장판 공식 사이트(`chiikawa.toho-movie.jp`)에 1080x1420 일러스트가 있어 그쪽을 쓴다.
아래쪽에 이름표와 소개 글이 붙어 있어 `scripts/movie-art.py` 가 그림 부분만 잘라낸다.
`sips --cropOffset` 은 넣은 값이 그대로 반영되지 않아 쓰지 않는다. 좌표를 직접 지정한다.

굿즈 이미지는 공식몰 CDN 에서 원본 그대로 온다. 카드에 170px 로 띄우면서 291KB 를 받고 있었다.
상품의 99% 가 Shopify CDN 에 있고 주소에 `width` 를 붙이면 그 폭으로 줄여 주므로,
실제 렌더 폭을 재서 1배·2배 두 벌을 `srcset` 에 넣는다 (`src/lib/image.ts`).
굿즈 목록 12장 기준 1,463KB → 87KB.

> 처음엔 무거운 게 제목 서체일 거라 짐작했는데 그건 156KB 였고 본문 서체가 991KB 였다.
> 한 탭을 재사용해 페이지를 옮겨 다니며 재면 폰트가 중복 집계된다. 페이지마다 새 컨텍스트로 재야 한다.

## 커서

`scripts/cursor.py` 가 캐릭터 얼굴로 커서 이미지를 만든다. 둘 다 일러스트를 쓴다.
기본은 극장판 공식 사이트의 캐릭터 아이콘으로, **이미 배경이 투명이라 벗겨 낼 필요가 없다.**
아이콘에는 캐릭터와 이름표가 함께 들어 있어 위쪽 덩어리만 쓰고,
목에 두른 풀잎 색이 나오는 줄에서 잘라 얼굴만 남긴다.

누를 수 있는 곳 위에서는 표정이 다른 일러스트로 바뀐다. 이쪽은 흰 원 안에 캐릭터가 든 배지라
원 바깥을 마스크로 지운 뒤 원 안쪽 가장자리에서 번지게 해 흰 원만 없앤다.
마스크 원을 원본보다 조금 줄여야 색 테두리가 남지 않는다.

커서 캐릭터는 사이드바에서 고르고 브라우저에 저장된다. 고른 값은 `<html data-cursor>` 로 들어가
CSS 변수만 바꾸므로, 커서를 쓰는 곳이 늘어도 규칙을 한 곳에서 관리한다.
브라우저가 커서 이미지를 못 읽을 때를 대비해 CSS 에 기본값을 반드시 남기고,
손가락으로 쓰는 화면에서는 커서 그림과 선택기를 모두 끈다.

## 디자인

아이보리 배경에 채도를 낮춘 파스텔 톤. 웹과 모바일 모두 대응한다.

홈의 3D 캐릭터는 `next/dynamic` 의 `ssr: false` 로 나눠 받는다.
정적 내보내기에는 서버 렌더 단계에서 `window` 가 없어 성능 문제 이전에 필수다.
받는 동안에는 같은 크기의 자리에 캐릭터 얼굴 이미지와 로딩 표시를 띄운다.
빈 칸을 두면 화면이 멈춘 것처럼 보이고 레이아웃도 밀린다.

### 레이아웃에서 두 번 물린 것

- 그리드 아이템의 기본값은 `min-width: auto` 라 내용보다 작아질 수 없다. 말줄임을 걸어도 안 먹는다. `min-width: 0` 을 준다
- 미디어쿼리는 명시도를 올려 주지 않는다. 기본 규칙보다 **위에** 쓰면 소스 순서상 나중 규칙이 이긴다

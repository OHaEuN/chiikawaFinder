# 운영 지표

포트폴리오로 쓸 수 있게, 무엇을 보고 무엇을 바꿀지 미리 정해 둔다.
숫자를 모으는 것 자체가 목적이 아니라, 다음에 무엇을 만들지 정하는 근거로 쓴다.

## 붙이는 법

분석 도구는 환경변수 하나만 채우면 붙는다. 비워 두면 스크립트가 아예 실려 나가지 않는다.

| 도구 | 환경변수 | 쿠키 동의 배너 | 비고 |
|---|---|---|---|
| Plausible | `NEXT_PUBLIC_PLAUSIBLE_DOMAIN` | 필요 없음 | 유료. 이벤트 속성까지 봄 |
| Umami Cloud | `NEXT_PUBLIC_UMAMI_ID` | 필요 없음 | 무료 구간 있음 |
| GA4 | `NEXT_PUBLIC_GA_ID` | 필요 | 무료. 설정이 번거로움 |

배포는 `.github/workflows/deploy.yml` 이 GitHub Pages로 올린다.
저장소 설정의 Variables 에 위 환경변수를 넣으면 빌드에 반영된다.

## 남기는 이벤트

| 이벤트 | 언제 | 무엇을 알 수 있나 |
|---|---|---|
| `goods_buy_click` | 굿즈 상세에서 구매 링크를 누를 때 | 어떤 상품이 실제 구매 의사로 이어지는지. 제휴 수익의 선행 지표 |
| `goods_search` | 굿즈 검색어 입력이 멈춘 뒤 | 무엇을 찾는지. 결과가 없는 검색어가 다음에 채울 데이터다 |
| `calculator_add_item` | 계산기에 상품을 담을 때 | 계산기를 실제로 쓰는지. 담기까지 갔는지 |
| `calculator_rate_groupbuy` | 공구 환율 프리셋을 누를 때 | 공구 수수료 비교가 실제 쓰임새인지 |
| `calculator_rate_market` | 실환율로 되돌릴 때 | 위와 비교해 어느 쪽을 더 보는지 |
| `place_directions` | 장소 상세에서 길찾기를 누를 때 | 오프라인 정보가 실제 방문으로 이어지는지 |
| `online_open` | 온라인 콘텐츠 링크를 누를 때 | 어떤 플랫폼 경로를 실제로 쓰는지 |

## 볼 지표

**들어오는지**
- 방문자 수와 유입 경로. 검색 유입이 늘면 데이터가 쌓인 효과다.
- 어느 페이지로 처음 들어오는지. 캘린더나 계산기로 바로 들어온다면 그게 이 사이트의 이유다.

**쓰는지**
- 계산기 도달 대비 `calculator_add_item` 비율. 담지 않고 나가면 상품 검색이 어렵다는 뜻이다.
- 굿즈 검색 중 결과 0건 비율. 이건 화면에서 직접 세야 하므로, 필요해지면 `goods_search_empty` 를 추가한다.

**다시 오는지**
- 발매일 전후의 방문자 변화. 발매 캘린더가 돌아올 이유가 되는지 본다.
- 9월 25일 할로윈 마스코트처럼 한정 발매가 있는 날이 자연 실험이 된다.

**돈이 되는지**
- `goods_buy_click` 수. 제휴 링크를 붙이기 전이라도 이 숫자가 곧 수익 상한이다.
- 제휴를 붙인 뒤에는 클릭 대비 전환을 각 제휴 대시보드에서 확인한다.

## 판단 기준

- 계산기를 담기까지 가는 비율이 낮으면, 상품 검색을 고치는 게 먼저다.
- 발매일에만 방문이 몰리고 평소에 없으면, 알림 기능이 다음이다.
- 검색어에 특정 캐릭터나 시리즈가 반복되면, 그 축으로 데이터를 더 채운다.
- 구매 클릭이 거의 없으면 제휴 가입은 뒤로 미룬다. 수익보다 트래픽이 먼저다.
